# serve — живые каналы, пульт, preview и take

    keyfill serve [канал.tsx ...] [--port 4748] [--host 127.0.0.1] [--token T] [--journal .keyfill/journal] [--resume]

Каналы — файлы `defineChannel` (keyfill docs channel): из аргументов (номера 1, 2, … по порядку) или
из `channels: { 1: 'channel.tsx' }` в keyfill.config.ts. Каждый канал идёт по своим часам кадра;
команда применяется на ближайшей границе кадра. Режим `must` — air (`--mode dev` — для отладки).
Первая строка stdout — JSON с адресом: `{"keyfill":1,"serve":"127.0.0.1:4748","channels":[1]}`.

## HTTP

| Путь | Что |
|---|---|
| `GET /` | версия и номера каналов |
| `GET /schema` | по каналам: stage, каталог, компоненты с JSON Schema пропсов и параметров команд, данные канала (`props`), слои состояний и состояния |
| `GET /state` | по каналам: кадр, слои (показанный, загруженный, уходящие, с текущими пропсами), состояние и данные канала, preview, журнал |
| `GET /monitor/<N>.png?scale=0.25[&preview=1]` | текущий кадр эфира (или preview) канала N; заголовок `X-Keyfill-Frame` — номер кадра эфира |
| `GET /ws` | WebSocket: команды и события |

## WebSocket `/ws`

Сообщение — JSON-объект. `channel` — номер канала (по умолчанию 1), `to` — `program` (эфир, по
умолчанию) или `preview` (отложенные), `id` — вернётся в ответе.

    {"id":"a1","cmd":"play","layer":20,"component":"LowerThird","props":{"name":"Анна"}}
    {"id":"a2","cmd":"update","layer":20,"props":{"role":"Ведущая"},"to":"preview"}
    {"id":"a3","cmd":"batch","cmds":[{"cmd":"stop","layer":20},{"cmd":"play","layer":10,"component":"Scoreboard","props":{...}}]}
    {"id":"a4","cmd":"take"}        отложенное — в эфир одной пачкой на одном кадре
    {"id":"a5","cmd":"discard"}     сбросить отложенное
    {"id":"a6","cmd":"state"}       {"id":"a7","cmd":"schema"}
    {"id":"a8","cmd":"state","name":"interview","to":"preview"}   состояние канала — в preview
    {"id":"a9","cmd":"update","props":{"homeScore":2}}             данные канала (без слоя)

Команды — как в журнале: load, play, next, stop, update, invoke, clear, state. `state` с `name` —
переход в состояние канала, без `name` — снимок (ответ как `/state`). `batch` — несколько
команд атомарно. Ответ — `{"type":"ack","id":…,"frame":…,"to":…,"results":[{cmd,status,errors}]}`:
`ok`; `rejected` — не исполнялась, ничего не изменилось; `failed` — упала в JS посреди исполнения.

Сервер шлёт всем клиентам:

- `hello` — при подключении;
- `event` — жизненный цикл экземпляров и таймлайнов, маркеры, emit: `{"t","frame","source","kind","name"}`;
- `state` — слои, состояние канала и данные после каждой принятой пачки;
- `preview` — отложенные команды, момент кадра preview и его диагностики;
- `diagnostic` — новая диагностика эфира (например, применённый `else`), один раз, пока держится.

## Preview и take

Preview — снимок эфира плюс отложенные команды. Отложенная команда сразу проверяется (отклонённая
в отложенные не попадает), а preview показывает итог — кадр, когда улеглись все in и уходы, —
и его диагностики: до эфира видно, что фамилия не влезет и в эфире применится `else[1]`.
Отложенные общие на канал. Эфир изменился — preview пересобирается.

## Журнал и подъём

Принятые команды дописываются в `--journal/ch<N>-<время UTC>.journal.jsonl` по ходу эфира: это
обычный журнал, `keyfill render` и `check` воспроизводят по нему эфир кадр в кадр. Кадр, который
видел оператор (`X-Keyfill-Frame: 1234`), — `keyfill render <журнал> --t 1234f --mode air`. `--resume` берёт последний
журнал канала, восстанавливает слои и данные к его концу и ставит их сразу «в эфир» — без
повторного in, таймлайны на своей первой остановке (`"instant": true` в первой пачке нового журнала).

## Доступ

По умолчанию слушает только 127.0.0.1, а запросы с чужим `Host` отклоняет (защита от DNS
rebinding). `--host 0.0.0.0` требует токен: `--token` или `KEYFILL_TOKEN`; клиент передаёт его
заголовком `Authorization: Bearer <токен>` или `?token=` (для WebSocket из браузера).
