# channel — канал, слои, журнал команд

Канал — один выход со своим stage и fps. Что на нём показано, решают команды: оператор ставит
графику на слои, меняет данные и снимает. Сцена (`defineScene`) — заранее собранная картинка;
канал — живой эфир.

    // channel.tsx
    import { defineChannel } from '@keyfill/core';
    export default defineChannel({
      stage: { ref: [1920, 1080] },
      fps: 50,
      fonts: [inter],
      systemFonts: false,
      timelines: [scoreboardMotion],
      components: [Scoreboard, LowerThird],   // каталог: что можно ставить на слои
    });

Слой — число, порядок наложения: больше — выше. На слое один показанный экземпляр.

| Команда | Что делает |
|---|---|
| `load` слой Компонент {props} | создать экземпляр, не показывая |
| `play` слой [Компонент {props}] | показать загруженный (или сразу этот); прежний уходит через `out` |
| `next` слой | снять остановку таймлайна: hold или цикл |
| `stop` слой | увести через `out`; после ухода экземпляр удаляется |
| `update` слой {props} | новые данные; изменения идут через `transition` |
| `invoke` слой команда {params} | команда компонента |
| `clear` [слой] | убрать без анимации: слой или весь канал |
| `state` имя | перейти в состояние канала (ниже) |
| `update` {props} без слоя | новые данные канала |

Пропсы и параметры проверяются по типам (`keyfill docs props`); каталог и схема —
`keyfill schema channel.tsx`.

## Состояния и данные

Оператор переключает не плашки, а состояние сцены. У канала есть данные (`props`) и состояния:
что стоит на слоях состояний в каждом из них.

    export default defineChannel({
      stage, fps, fonts,
      props: { home: prop.string({ default: 'Динамо' }), homeScore: prop.number({ default: 0 }), guest: prop.string({ default: '' }) },
      layers: { score: 10, lower: 20 },
      states: (d) => ({
        live:      { score: Scoreboard.with({ home: d.home, homeScore: d.homeScore, period: '1-й тайм' }) },
        interview: { score: Scoreboard.with({ home: d.home, homeScore: d.homeScore, period: '1-й тайм' }),
                     lower: LowerThird.with({ name: d.guest, role: 'Гость', live: true }) },
      }),
    });

- `state interview` — переход как разница двух состояний: что ушло из состояния, уходит через
  `out`; что пришло — входит; тот же компонент на том же слое остаётся тем же экземпляром и
  переходит на пропсы нового состояния через `transition` (и `transition.layout`).
- Пропсы в `with` — значения или аксессоры данных (`d.guest` или функция: ``() => `${d.home()} — ${d.away()}` ``):
  `update {"homeScore": 2}` без слоя меняет данные, и все плашки, которые на них смотрят,
  обновляются сами.
- Прерывание: новый `state` посреди перехода считается от того, что сейчас на слоях. Уходящая
  плашка, которая снова нужна, разворачивается с текущего места — второй копии нет.
- Слои из `layers` ведут состояния: `load`, `play`, `stop`, `update`, `clear` с этим слоем
  отклоняются с подсказкой; `invoke` (гол) и `next` работают. `clear` без слоя снимает всё.
- Привязки проверяются при загрузке канала: состояние, которому не хватает пропса, — ошибка
  канала с местом (`состояние on, слой main: не задан обязательный пропс "text"`).
- У каждого пропса данных нужно начальное значение (`default` или `defaults`).
- Снимок (`/state`, preview, `--resume`) — данные и имя состояния: восстановление — это
  `update` данных и `state <имя>` сразу «в эфир».

## Хореография переходов

Когда начинается каждый шаг перехода (`слой:out`, `слой:in`, `слой:update`), решает правило
из `transitions`. Без правила — `together()`: всё в момент команды.

    import { overlap, sequence } from '@keyfill/core';
    transitions: {
      default: overlap(0.15),                     // in за 0.15 с до конца всех out
      'pregame -> live': sequence(0.1),           // in через 0.1 с после конца всех out
      'live -> replay': ({ out, enter, update }) => [
        enter('replay', { after: 'lower:out', offset: -0.1 }),   // от конца шага
        update('score', { with: 'replay:in', offset: 0.05 }),    // от начала шага
        out('lower', { at: 0.2 }),                               // секунд от начала перехода
      ],
      '* -> break': sequence(),                   // * — любое состояние
    },

- Правило ищется так: точная пара, `from -> *`, `* -> to`, `* -> *`, `default`, `together()`.
- Шаги, не названные в правиле, начинаются в момент команды. Длительности `in` и `out` ядро
  берёт из presence и таймлайнов компонентов; `update` — мгновенный шаг.
- Ядро сводит расписание сразу, в момент `state`; шаги исполняются в свои точные моменты (между
  кадрами тоже), поэтому журнал воспроизводит переход так же. В дампе кадра, пока переход
  идёт, — диаграмма:

      переход pregame → live  @2s  (sequence +0.1 (pregame -> live))
        score  in      0.35–1.6    Scoreboard#1  (после всех out +0.1)
        lower  out     0–0.25      LowerThird#1

- Прерывание: новый `state` отменяет неначатые шаги — невошедшая плашка не показывается,
  неушедшая остаётся на месте, — и новая разница считается от того, что реально в кадре.
- При загрузке канала проверяется: слои из `layers`; для пары двух названных состояний — что
  шаг в этом переходе бывает (`шага a:in в этом переходе нет — на слое a здесь только out`);
  циклы (`цикл — a:out ждёт b:in, b:in ждёт a:out`).
- Входящая плашка, которая наезжает на уходящую с другого слоя в то же время, — warn
  `transition.overlap` с подсказкой (`keyfill explain transition.overlap`).

Пример — `examples/match` (`keyfill filmstrip examples/match/show.journal.jsonl --t 0..11`).

## Журнал

Команды канала пишутся в журнал `*.journal.jsonl` (JSON Lines): заголовок, затем пачки по кадрам.
Пачка применяется атомарно на одном кадре.

    {"keyfill":1,"channel":"channel.tsx","seed":1,"now":0}
    {"frame":0,"cmds":[{"cmd":"play","layer":10,"component":"Scoreboard","props":{"home":"Динамо","away":"Крылья","period":"1-й тайм"}}]}
    {"frame":60,"cmd":"next","layer":10}
    {"frame":110,"cmd":"invoke","layer":10,"command":"goal","params":{"side":"home"}}
    {"frame":250,"cmd":"stop","layer":10}

Строка с `cmd` — пачка из одной команды. `channel` — путь от каталога журнала; `seed` и `now` —
сид и часы записи, воспроизведение берёт их отсюда.

Журнал — обычный `<entry>`: `render`, `dump`, `inspect`, `check`, `filmstrip`, `video`, `perf`,
`view`, `schema`. Воспроизведение детерминировано: те же кадры, что видел эфир. Без `--t` кадр —
когда успокоилось то, что запустила последняя пачка.

- Отклонённая команда (слой пуст, нет компонента, неверные пропсы) в живой сессии не пишется;
  в журнале, написанном руками, — ошибка `channel.rejected` с кадром и причиной.
- Команда, упавшая в JS посреди исполнения, остаётся в журнале с полем `error`: её частичный
  эффект был в эфире, и воспроизведение повторяет его. Расхождение с записью — `journal.diverged`.

`keyfill serve` принимает те же команды по WebSocket и пишет этот же журнал (keyfill docs serve).
