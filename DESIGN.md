# keyfill — дизайн v0

Нативный движок рендера интерфейсов и графики. Автор описывает сцену в TSX, keyfill рисует её без браузера и отдаёт кадры любому потребителю видео: окну, файлу, NDI/Spout/SDI, экрану киоска.

Ориентир по архитектуре — Panorama UI (Valve), но область применения другая: эфирная и стрим-графика, рендер роликов, табло, signage.

**Главная идея: основной автор — AI-агент.** Агент пишет графику, анимации, логику и компоненты. Поэтому API проектируется не под привычки веб-разработчика, а под короткий и надёжный цикл «написал → проверил». Человек читает и ревьюит, агент пишет и проверяет.

---

## 1. Принципы

1. **Локальность.** Итоговый вид узла определяется тем, что написано на самом узле, и явно подключёнными токенами. Нет каскада, специфичности и неявного наследования.
2. **Типизация.** Всё, что можно проверить типами, проверяется типами. Никаких строковых микроязыков (`"0 4px 8px rgba(...)"`). Ошибка должна ловиться `tsc` до рендера.
3. **Наблюдаемость.** Агент плохо видит пиксели и хорошо читает структуры. Любое состояние сцены доступно как данные: геометрия, итоговые значения, их происхождение, нарушения.
4. **Детерминизм.** Кадр — чистая функция от (код, данные, t). В режиме рендера в файл кадр N всегда одинаковый.
5. **Эфир не падает.** Ошибки в dev и тестах громкие, в эфире — деградация по заранее заданному правилу и метрика.
6. **Альфа — первый класс.** Весь пайплайн в premultiplied alpha, выход fill + key.
7. **Словарь CSS, механика своя.** Названия свойств знакомые (`padding`, `gap`, `radius`), потому что агент знает их лучше всего. Механика каскада и строковых значений выброшена.

## 3. Время

Две реализации одного `Clock`:

- **live** — монотонные часы системы, кадры по vsync или по таймеру выхода (NDI/SDI диктуют свою частоту);
- **deterministic** — `t = frame / fps`, кадры идут так быстро, как получается отрендерить.

JS не видит реальное время ни в одном режиме. `Date.now()`, `performance.now()`, `setTimeout`, `requestAnimationFrame` подменены на часы keyfill, `Math.random()` — на сид из конфига рендера. Внешние данные в deterministic-режиме подаются как запись (`data track`) с метками времени, чтобы рендер был воспроизводимым.

Движение считается в ядре и вычислимо в любой момент `t` без проигрывания с начала. Пружины решаются аналитически (затухающий осциллятор в замкнутой форме), а не пошаговой симуляцией.

Времени в JS нет совсем: `time()` и `frame()` убраны из API (M2). JS вызывается при монтировании и на командах сценария, а не на кадрах; числа и часы, которые идут сами, считает ядро (`count()`, `clock()` — M2c). Кадр в момент `t` получается так: события до `t` (команды сценария, окончания фаз) обрабатываются по порядку, затем все движения вычисляются в `t` в замкнутой форме. Поэтому кадр не зависит от того, какие кадры рендерились перед ним, — это проверяет тест.

## 4. Компоненты и сигналы

Модель как в Solid: компонент выполняется один раз, реактивность точечная, виртуального DOM нет.

- `signal(v)`, `computed(fn)`, `effect(fn)`, `batch(fn)` — в `@keyfill/core`.
- В v0 нет компиляции JSX в стиле Solid (Babel-плагина). Реактивное значение в пропсе — это функция-аксессор: `<Text>{name}</Text>`, где `name` — сигнал. Рантайм видит функцию и подписывается. Это проще в сборке (только esbuild) и прозрачнее для агента: реактивность видна в коде.
- JSX dev-рантайм (`jsxDEV`) передаёт `file:line:col` каждого элемента. Это основа для provenance и структурных ошибок.
- **Ловушка модели «выполняется один раз»:** `live() && layer` прямо в `view` вычисляется однажды и больше не обновится. Защита в два слоя: в API есть реактивные конструкции (`on(live, layer)`, `when={live}`, аксессоры), а dev-рантайм ловит чтение сигнала вне отслеживаемого контекста во время `view` и выдаёт структурную ошибку с `file:line` и подсказкой. Агент чаще всего ошибётся именно здесь, поэтому это проверка движка, а не совет в документации.
- Пропсы объявляются схемой, описанной в рантайме (`{ name: String, side: prop.enum(['home', 'away']), score: prop.number({ min: 0, default: 0 }) }`, с M4a): из неё tsc выводит тип, keyfill — JSON Schema для пульта и проверку значений из команд. Внутри компонента каждый пропс — аксессор, снаружи можно передать значение или сигнал; пропс с `default` можно не передавать.

### Примитивы v0

`Box`, `Text` (с вложенными `Span`), `Image`, `Shape` (path). Видео-источник как примитив — позже.

### Списки по данным (с M4a+)

`view` выполняется один раз, поэтому набор узлов по данным строит `For` — внутри `Box`, рядом с обычными детьми:

```tsx
<For each={p.teams} by={(t) => t.id}>
  {(t, i) => <Row place={() => i() + 1} name={() => t().name} points={() => t().points} />}
</For>
```

Ключ решает, что такое «тот же элемент» при новых данных: тот же ключ — те же узлы с новыми значениями (через `transition`, `count`); новый — монтирование и `in` (своё или каскад `stagger` контейнера); пропавший — `out` (своё или каскад `out` контейнера) и удаление после ухода, а пока уходит — на своём месте; новый порядок — переставляются только сдвинутые (наибольшая возрастающая подпоследовательность стоит). `by` обязателен для объектов: ключ по месту в списке переписал бы все строки ниже удалённой, и агент ошибся бы здесь молча. Повтор ключа — warn `list.duplicate-key`. Адрес элемента — по ключу (`box[key=zen]`), а индексы обычных соседей ключевые элементы не сдвигают: `inspect`, `check` и снапшоты указывают на тот же элемент при любом порядке. Плавный переезд при перестановке и после ухода соседа — `transition.layout` на корне элемента (с M5a, раздел 8). Атрибут называется `by`, а не `key`: `key` в JSX забирает компилятор.

## 5. Стили: `look`

```tsx
<Box look={[theme.panel, on(live, theme.panelLive), { radius: 16 }]} />
```

- `look` — значение или список слоёв. Слои применяются по порядку, побеждает последний. Ложные значения (`false`, `null`, `undefined`) пропускаются. Состояния пишутся через `on(signal, layer)` — это реактивный слой, а не вычисленное один раз выражение.
- Набор свойств зависит от примитива: у `Box` нет `font`, потому что без наследования шрифт на контейнере ничего не делает. Ошибка ловится типами.
- **Нет наследования**, кроме одного явного случая: `Span` внутри `Text` наследует текстовые свойства своего `Text` и переопределяет только заданные (`font`, `size`, `weight`, `color`, `tracking`, `case`). Больше ничего от родителя не приходит. `Span` не вкладывается в `Span`.
- Все значения структурные и типизированные: `shadow: { y: 4, blur: 8, color }`, `padding: [16, 24]`.
- Тема — типизированный объект токенов (`theme.color.accent`, `theme.type.title`). Смена темы — это смена сигнала, без перезапуска.
- Для каждого итогового значения ядро хранит **provenance**: из какого слоя оно пришло (`theme.ts:12` → `LowerThird.tsx:8 look[1]`).

## 6. Единицы, сцена, раскладка

- **Stage** задаёт опорный кадр (`ref: [1920, 1080]`), реальное разрешение выхода и safe areas. Все длины пишутся в логических единицах опорного кадра; выход 4K — масштаб ×2. Для вертикального формата — свой `ref`.
- Safe areas по EBU R95: `actionSafe` 93%, `titleSafe` (graphics safe) 90%. Можно переопределить.
- **Позиционирование** — гибрид: внутри контейнеров обычный flex/grid (Taffy), а якорь `anchor={{ to, at, self?, offset? }}` ставит узел относительно цели. `to` — `stage`, `actionSafe`, `titleSafe`, `parent` (по умолчанию) или часть компонента (`part.status`).
  - Верхнеуровневый узел раскладывается в пределах цели и ставится якорем.
  - Узел внутри контейнера выносится из потока и ставится относительно цели.
  - Внутри `stack()` якорь к родителю — это ячейка с выравниванием: дети накладываются, `at` задаёт угол, `offset` сдвигает.
  - Якорь к части компонента ставится вторым проходом, когда цель уже разложена. Цепочки (якорь к части, которая сама привязана к части) не поддерживаются.
- **grid** — `grid({ columns, rows?, gap? })`, дорожки: число, `pct(n)`, `{ fr: n }`, `'auto'`; `gap` — число или `[x, y]`. Ячейка ребёнка — `cell={{ col, row, colSpan, rowSpan }}` (с 1), без неё — по порядку.
- **fit** для текста: `fit={{ shrinkTo: 32, lines: 2, then: 'ellipsis' }}`. Подбирается наибольший кегль с шагом 0.5 между `shrinkTo` и `size`, при котором текст укладывается в `lines` строк (по умолчанию 1). Не вышло даже на `shrinkTo` — `then: 'ellipsis'` обрезает с «…», `'clip'` обрезает по блоку, без `then` текст помечается как непоместившийся (его ловит `must.fit`).
- **Шрифты** — ресурс сцены и подключаются импортом: `import inter from './fonts/Inter-Regular.otf'`, затем `defineScene({ fonts: [inter], systemFonts: false })`. Путь разрешает бандлер относительно импортирующего файла, как у любого импорта, а опечатка в пути — ошибка сборки с местом в исходнике. Строковый путь в `fonts` не пройдёт tsc. Имена семейств берутся из самих файлов. Для детерминированного рендера системные шрифты выключаются.

## 7. Утверждения: `must` / `else`

```tsx
<Text must={{ fit: true, contrast: 4.5 }}
      else={[{ shrinkTo: 32 }, { shrinkTo: 32, lines: 2 }, { shrinkTo: 32, lines: 2, ellipsis: true }]}>
  {name}
</Text>
```

Правила: `fit` (текст или дети не переполняют контентный блок), `inside` (узел внутри цели: safe area, `parent`, часть компонента), `contrast` (WCAG-контраст самого слабого цвета текста, включая Span, к фону под ним), `visible` (ненулевой размер, хотя бы частично в кадре, итоговая прозрачность больше нуля).

Фон для `contrast` считается по подложкам предков с учётом их прозрачности, а не по пикселям. Если под текстом остаётся прозрачность (обычный случай для оверлея), проверка невозможна: выдаётся info с подсказкой передать подложку эфира через `--bg`.

Варианты `else` **независимые**, как `ViewThatFits` в SwiftUI: `else[k]` применяется сам по себе, без вариантов перед ним, поверх собственных `fit` и `look` узла. Эскалацию пишут явно: `[{ shrinkTo: 28 }, { shrinkTo: 28, lines: 2 }, { shrinkTo: 28, lines: 2, ellipsis: true }]`. Так каждый вариант читается без контекста, а подсказка «else[1] это исправляет» указывает ровно на то, что применится.

- **dev** (`--mode dev`, по умолчанию, и тесты): нарушение — ошибка с адресом узла и местом в исходнике. Ядро само перебирает варианты `else` и пишет в подсказке, какой из них исправил бы нарушение. Кадр рисуется как есть.
- **эфир** (`--mode air`): применяется первый вариант `else`, при котором `must` выполнен; если ни один не помог — последний. Применённый шаг виден в дампе и в предупреждении. Метрика `keyfill_must_violation{rule,node}` появится вместе с рантаймом управления (M4); в событиях она уже видна оператору.

## 8. Движение

Три уровня, все детерминированы.

| Уровень | Где | Для чего |
|---|---|---|
| `transition` | в `look` или на узле | Как свойство интерполируется при изменении данных |
| `presence` | на узле или в `component()` | Появление `in`, цикл `loop`, уход `out`. Узел удаляется только после окончания `out` |
| `timeline` | отдельный `*.motion.ts` | Длинные постановки: дорожки, ключевые кадры, маркеры, перемотка |

- Компонент объявляет свои части: `parts: ['panel', 'title']`. В `view` узлу дают имя через `name={part.panel}` (строкой нельзя), а таймлайн адресует части строками, которые tsc сверяет со списком: `timeline(LowerThird, ({ at }) => …)`, где `at(0, 'logo', …)` — ошибка типов, а не молчаливый no-op. Полный путь в дампе — `LowerThird#1/panel`.
- Маркеры (`in`, `loop`, `out` и свои) — это то, чем управляет оператор эфира: `play` → `in`, `next` → следующий маркер, `stop` → `out`. Модель совместима с привычным CasparCG-циклом play / next / stop / update.
- Изинги: `tween(duration, ease)`, `spring.{snappy,gentle,bouncy}` и `spring({ stiffness, damping, mass })`.

### Как исполняется (с M2a)

- **Два слоя значений.** `presence` (а в M2b и таймлайн) работает поверх `look`: `x`, `y`, `rotate` — сдвиг, `scale`, `opacity` — множитель, `reveal` — доля видимых символов; `width`, `height`, `radius`, `background`, `color` перекрывают значение `look`. Этот слой не участвует в `must`: утверждения говорят о графике в эфире, а не о промежуточном кадре появления. `transition` анимирует само значение `look`, когда изменились данные; без `transition` значение меняется скачком.
- **Жизненный цикл сцены:** `loaded` (узлы стоят в первом кадре своего `in`) → `play` → `in` → `loop` → `stop` → `out` → `removed`. При `stop` уходят узлы, у которых есть `out`; остальные остаются на экране, пока сцена не снята после последнего `out`. Узел, у которого `when` стал false, уходит через свой `out` и только потом скрывается; когда `when` снова true — проигрывает `in`.
- **Анимация геометрии (с M5a)** — `transition: { layout: easing }`. Когда раскладка перестроилась, узел едет к новому месту относительно родителя, а `Box` — ещё и к новому размеру; текст только едет: на кадрах переезда он не переразбивается и не меняет кегль. Без `layout` место меняется скачком, `all` геометрию не включает. Устроено как FLIP: раскладка каждого кадра — конечная, а узел получает смещение от неё к месту, где его было видно, и это смещение затухает до нуля. Поэтому переезд не мешает тому, что меняет раскладку непрерывно (часы, `count`, переходы `width`), и после конца переезда кадр равен раскладке. Узел без своего `layout` едет вместе с родителем; узел с якорем к части едет вместе с частью. Раскладка снимается до и после изменения только в известные моменты — пачка команд (сценарий, журнал, живая команда) и уход узла из раскладки (конец `out`, снятие экземпляра), а не на кадрах: кадр зависит только от момента. Две пачки на одном кадре дают то же, что одна склеенная. `must` проверяет место в раскладке (`rect`), а рисуется и подсвечивается видимое (`shown`). Сверка раскладки не запускается, пока в сцене нет ни одного `layout`.
- **Прерывание** — правило для узлов на экране: новое движение канала стартует из текущего значения, пружина получает текущую скорость. Узел, которого не было на экране (до play или после ухода), проигрывает `in` с объявленных значений. Бесконечные качания (`pulse`) всегда идут по объявленным значениям.
- **Сценарий.** Без него сцена получает `play` в момент 0. Сценарий — `*.cues.ts` с `cues(scene, ({ at }) => [...])` (tsc проверяет команды и пропсы по компоненту) или короткая форма `--cue "0 play; 1.2 next; 2.5 stop Scoreboard"`. Команды применяются на границе кадра.
- **Кадр по умолчанию** у `render`, `dump`, `inspect`, `check` — «в эфире»: момент, когда закончились все `in` первого `play`. Нужен другой момент — `--t` (`1.2`, `60f`, `settled+0.5`; грамматика — в разделе «CLI как контракт»).

### Прерывания, циклы, события, команды

Всё ниже — данные, которые исполняет ядро. JS в покадровом цикле не участвует: он работает только на командах, событиях и изменении данных.

- **Прерывания.** Любое движение стартует из текущего значения. `stop` во время `in` начинает `out` с того места, где графика сейчас; `update` во время перехода перенацеливает его, пружина сохраняет скорость. Команды применяются на границе кадра, поэтому результат детерминирован.
- **Сегменты и циклы.** Маркеры режут таймлайн на сегменты. Цикл задаётся явно, остановки ждут `next`. Таймлайн подключается к сцене: `defineScene({ timelines: [scoreboardMotion] })`; у каждого экземпляра компонента своё воспроизведение. Рабочий пример — [examples/scoreboard/Scoreboard.motion.ts](examples/scoreboard/Scoreboard.motion.ts):

  ```ts
  export default timeline(Scoreboard, ({ at, emit }) => ({
    keys: [/* … */],
    markers: { ready: 0.7, loop: 1.0, out: 2.6, goalHome: 3.0, goalAway: 4.4 },
    loop: { from: 'loop', to: 'out', mode: 'repeat' },   // или 'pingpong', count: n; без loop — loop..out по умолчанию
    holds: ['ready'],                                    // стоп на маркере до next
    events: [emit(0.6, 'reveal-done')],
  }));
  ```

  Правила воспроизведения (с M2b):
  - `play` — от 0 вперёд. На маркере из `holds` стоп до `next`, отрезок цикла повторяется до `next`, за маркер `out` обычное воспроизведение не заходит.
  - `next` снимает текущую остановку: продолжить после hold или выйти из цикла. Если остановки нет, событие `ignored`.
  - `stop` — прыжок на `out` и воспроизведение до следующего маркера (или конца), затем экземпляр снят.
  - `ctx.play('goalHome')` в команде играет сегмент от маркера до следующего и возвращает воспроизведение туда, где оно было: в цикл, на hold.
  - Прыжки (`stop`, сегмент) продолжают каналы с текущих значений. Каналы, у которых после прыжка нет ключей, доигрывают своё движение во времени сцены. Повтор цикла идёт по исходным ключам: цикл задуман бесшовным.
  - Маркер, на котором кончается сегмент, `out` или виток цикла, не считается пройденным.
  - Слой таймлайна складывается с presence: сдвиги суммируются, множители перемножаются. `presence` корня компонента с таймлайном не исполняется (info `motion.timeline`).
  - В грамматике времени маркер означает момент, когда воспроизведение впервые его проходит: `--t goalHome+0.1`.

- **События.** Жизненный цикл (`state`: loaded, in, loop, hold, segment, out, finished, removed; у сцены — playing, stopping, removed), прохождение маркера (`marker`), свои события (`emit` из таймлайна и `ctx.emit` из команды), `ignored` для команд без эффекта. Каждое событие несёт точный момент, даже если между кадрами. Дамп показывает последние события к моменту кадра; в M4 они уходят клиентам управления и в журнал.
- **Команды компонента** — то, что пульт показывает как действия с параметрами. Параметры типизированы, а в сценарии их проверяет tsc: `at(2.2, 'invoke', Scoreboard, 'goal', { side: 'home' })`.

  ```tsx
  component({
    name: 'Scoreboard',
    props: { /* … */ },
    commands: {
      goal: {
        params: { side: String },                        // prop.enum(['home', 'away']) — с рантайм-типами в M4
        run: ({ side }, ctx) => {
          ctx.set({ homeScore: ctx.props.homeScore() + 1 });   // как update: изменения идут через transition
          ctx.play('goalHome');                               // сегмент таймлайна
          ctx.emit('goal');
        },
      },
    },
    view: /* … */,
  });
  ```

  `ctx`: `props` (аксессоры), `set(patch)`, `play(marker?)`, `next()`, `stop()`, `emit(name, data?)`. Команды движения исполняются в момент команды сценария, после изменений данных.

- **Каскад:** `presence={{ in: stagger(0.06, fade([0, 1])) }}` на контейнере — каждый видимый ребёнок получает то же движение со сдвигом `i·step` (`reverse` — с последнего). Длительность `in` контейнера включает весь каскад. До play дети стоят в первом кадре каскада.
- **Анимированные числа:** `<Text>{count(homeScore, { easing: tween(0.6), format: '0' })}</Text>` — при смене значения ядро ведёт число к новому, JS на кадрах не вызывается. Формат: `'0'`, `'0.0'`, `'00'`.
- **Часы и таймеры:** `<Text>{clock({ from: 67 * 60, running, format: 'mm:ss' })}</Text>` — значение в секундах идёт само со скоростью `rate`, пока `running`. Смена `from` сбрасывает часы, пауза и пуск продолжают с текущего значения. `min`/`max` останавливают часы; обратный отсчёт (`rate: -1`) округляется вверх, чтобы 0:00 появлялось ровно в конце. Форматы: `mm:ss`, `m:ss`, `h:mm:ss`, `ss.0`. `count` и `clock` пишутся прямо в `<Text>`, не внутри `Span`.

## 9. Рантайм, управление и внешние данные

`keyfill serve <проект>` — долгоживущий процесс. Пульт управления (ПУ) — отдельное приложение, keyfill даёт ему только API. Модель — как в CasparCG:

| Понятие | Что это |
|---|---|
| Канал | Выход со своим stage, часами, разрешением и fps; подключённые выходы: окно, NDI, ffmpeg, превью |
| Слой | Целое число на канале, порядок наложения; на слое не больше одного экземпляра |
| Экземпляр | Компонент из каталога проекта с пропсами; жизненный цикл `loaded → in → loop ⇄ hold → out → removed` |

Канал описывается файлом `channel.tsx` (с M4a): `defineChannel({ stage, fps, fonts, systemFonts, timelines, components: [Scoreboard, LowerThird] })`. `components` — каталог: что можно ставить на слои; `keyfill schema channel.tsx --json` даёт по нему JSON Schema пропсов и параметров команд. С M5b здесь же данные канала (`props`), слои состояний (`layers`) и состояния (`states`), в M5c — `transitions` (раздел 9.1).

**Команды** — JSON по WebSocket. У каждой есть `id`, ответ — подтверждение или структурная ошибка в том же формате, что диагностики. Ответ различает три исхода: `ok` — исполнена и записана в журнал; `rejected` — не исполнялась (слой пуст, компонента нет в каталоге, пропсы не подходят к типам), состояние не менялось, в журнал не попала; `failed` — упала в JS посреди исполнения, частичный эффект остался, команда записана в журнал с `error`, и воспроизведение повторяет её.

| Команда | Действие |
|---|---|
| `load channel-layer Component {props}` | Создать экземпляр, не показывая; прежний загруженный на этом слое удаляется |
| `play channel-layer [Component {props}]` | Показать загруженный (с компонентом — загрузить и показать): на занятом слое старый экземпляр уходит через `out`, новый входит; на этом же слое новый рисуется поверх уходящего |
| `next channel-layer` | Отпустить остановку `hold`, перейти к следующему сегменту |
| `stop channel-layer` | Запустить `out` из текущего состояния; после ухода экземпляр удаляется (узлы, движение, эффекты JS) |
| `update channel-layer {props}` | Поменять пропсы показанного (если его нет — загруженного); изменения идут через `transition` |
| `invoke channel-layer command {params}` | Вызвать команду компонента (адресат — как у `update`) |
| `clear channel[-layer]` | Убрать без анимации |
| `state channel name` | Перейти в состояние сцены (с M5b, раздел 9.1) |
| `update channel {props}` | Без слоя — данные канала (с M5b): все плашки, привязанные к ним, обновляются сами |

**События** приходят по тому же сокету: `state`, `marker`, `emit`, `finished`, диагностики (например, применённый в эфире `else`), состояние выходов (пропущенные кадры).

**HTTP:**

- `GET /schema` — каталог компонентов: пропсы, части, маркеры, команды с параметрами, в виде JSON Schema. По нему любой пульт строит формы и кнопки.
- `GET /state` — что на каких слоях и в каком состоянии.
- `GET /monitor/{channel}` — поток эфира в низком разрешении для оператора (раньше назывался `/preview`; preview теперь — механизм ниже).

Следствие для API компонентов: `prop<T>()` описывает тип только для tsc, схему из него не получить. Поэтому в M4 типы пропсов становятся описываемыми в рантайме: `prop.string()`, `prop.number({ min, max })`, `prop.enum([...])`, `prop.list(...)`, `prop.object({...})`, `prop.image()`; TS-тип выводится из них. Конструкторы `String`, `Number`, `Boolean` остаются как короткая запись.

**Журнал команд** (с M4a). Принятые команды пишутся пачками с номером кадра канала в `*.journal.jsonl` — JSON Lines: заголовок `{"keyfill":1,"channel":"channel.tsx","seed":1,"now":0}`, затем `{"frame":110,"cmds":[{"cmd":"invoke","layer":10,"command":"goal","params":{"side":"home"}}]}` (строка с одной командой — `{"frame":60,"cmd":"next","layer":10}`). Канал известен из заголовка, поэтому в журнале слой — просто число. Пачка применяется атомарно, на одном кадре. Воспроизведение журнала даёт те же кадры (дерево, значения, события, пиксели — это проверяет тест), поэтому живая сессия становится данными: журнал — обычный `<entry>` для `render`, `dump`, `check`, `video`, `view`.

**Снимок канала** (с M4a): что на каких слоях (показанный, загруженный, уходящие), с какими текущими пропсами (после `update`, команд и `ctx.set`) и в каком состоянии. Компонент меняет только свои пропсы и воспроизведение, поэтому снимка хватает, чтобы поставить ту же картинку заново: `State::to_batch` даёт команды восстановления. Из снимка строятся `/state`, preview и подъём `keyfill serve` после сбоя.

**Preview и take** (M4b). Preview — теневая копия канала: снимок эфира плюс отложенные команды. Оператор шлёт команды не в эфир, а в отложенные: `play`, `update` (данные — такое же изменение, как появление плашки), `stop`. Preview сразу показывает итог — кадр «в эфире» (`settled`), без ожидания `in`, а при желании и сам переход. На отложенном состоянии прогоняется `check`: оператор до эфира видит, что фамилия не влезет и в эфире применится `else[1]`. **Take** применяет всю пачку к эфиру атомарно, на одном кадре; **discard** сбрасывает её. Отложенные команды общие на канал, как PVW-шина видеомикшера; свои у каждого клиента — позже. Данные из источников (M6) идут в эфир сразу, preview их зеркалит; одобрение данных с фидов — в M6. Команды, которым preview не нужен, идут в эфир напрямую.

**Доступ.** По умолчанию API слушает только localhost; для сети — токен.

**Рандаун** (сценарий с автоматикой: «показать, через 5 с убрать, следующая») — позже, отдельным слоем поверх тех же команд.

## 9.1. Согласование компонентов и состояния сцены (M5)

События — не основной механизм совместной работы. Цепочка «A закончил `out` → запусти `in` у B» прячет зависимости в коде: раскадровку перехода не увидеть заранее, агент не может её проверить, а прерывание посреди цепочки даёт гонки. Компоненты согласуются тремя декларативными механизмами.

**1. Общие данные.** Сигналы, на которые смотрят несколько компонентов (`live`, счёт), связывают их реактивно, без событий.

**2. Состояния сцены на уровне канала** (с M5b). Оператор переключает не отдельные плашки, а состояния, и меняет данные канала. Канал описывается в TSX:

```tsx
export default defineChannel({
  props: { home: String, homeScore: prop.number({ default: 0 }), guest: prop.string({ default: '' }) },
  layers: { score: 10, lower: 20, replay: 30 },
  states: (d) => ({
    pregame: { score: Scoreboard.with({ home: d.home, size: 'big' }) },
    live:    { score: Scoreboard.with({ home: d.home, homeScore: d.homeScore, size: 'compact' }), lower: LowerThird.with({ name: d.guest, role: 'Гость' }) },
    replay:  { score: Scoreboard.with({ home: d.home, homeScore: d.homeScore, size: 'compact' }), replay: ReplayWipe.with({}) },
  }),
  transitions: {   // M5c
    default: overlap(0.15),
    'live -> replay': ({ out, enter }) => [
      out('lower'),
      enter('replay', { after: 'lower:out', offset: -0.1 }),
    ],
  },
});
```

Переход ядро вычисляет как разницу двух состояний: ушло → `out`, пришло → `in`, осталось с новыми пропсами → `update` через `transition`, осталось, но переехало → морфинг (табло плавно уходит из центра в угол, а не исчезает и появляется). Морфинг не отдельный механизм, а композиция (M5d): непрерывность — это тождество экземпляра, облик меняет пропс, место — якорь состояния (`with(props, { anchor })`), геометрию ведёт `transition.layout`, сменное содержимое — дети с `when` и `in`. Пульт шлёт `state 1 replay`. Слои, перечисленные в `layers` канала, управляются только состояниями: прямые `load`, `play`, `stop`, `update`, `clear` на них — отказ с подсказкой, `invoke` и `next` работают; остальные слои доступны командам из раздела 9.

Пропсы в `with` — значения или аксессоры данных канала. Графика — функция двух рычагов оператора: имени состояния и данных. Поэтому новая плашка в новом состоянии сразу знает текущий счёт, а снимок канала — это данные и имя состояния (плюс свободные слои).

**3. Хореография как зависимость во времени.** Анимация начинается не в абсолютный момент, а относительно маркеров других анимаций: `after: 'lower:out'`, `with: 'score:in'`, `offset` — как позиционный параметр в GSAP. Ядро сводит переход в одно расписание до его начала, и дамп показывает его как диаграмму:

```
переход live → replay
  lower    out    0.00–0.25
  replay   in     0.15–0.60   (after lower:out −0.1)
  score    morph  0.00–0.40   (общий элемент: compact → corner)
```

`check` ловит циклы («A ждёт B, B ждёт A») и конфликты («replay въезжает, пока lower ещё занимает ту же область»).

Как сделано (M5c): шаги перехода — `слой:out`, `слой:in`, `слой:update`; `after` — от конца шага, `with` — от начала, `at` — от начала перехода, `offset` сдвигает. Готовые правила — `together()` (по умолчанию: всё в момент команды), `sequence(gap)` и `overlap(seconds)`; пары — `'live -> replay'`, `*` — любое состояние. Циклы и шаги, которых в переходе не бывает, ловит загрузка канала (раньше `check`, с местом в правиле); конфликты областей — warn `transition.overlap` в момент перехода, по раскладке входящего и уходящего.

К этому же относится **зависимость через раскладку**: компонент, привязанный якорем к части другого экземпляра (`Scoreboard#1/panel`), плавно следует за ней, когда она меняет размер или место. С M5d это якорь состояния к части другого слоя: `Tag.with(props, { anchor: { to: 'score:panel', ... } })`.

Все связи между элементами объявлены в канале и имеют по одному механизму: **данные** — пропсы канала, **время** — шаги переходов, **место** — якоря состояний, **тождество** — тот же компонент на том же слое. Сложность — в композиции этих четырёх, а не в особых случаях ядра. Так M5d отказалась от общих элементов (`share`, как `layoutId`): они давали второй механизм тождества — глобальные строки во `view`, — и для приличного вида требовали особых случаев (гасить `in` контейнеров, глушить таймлайн, переставлять шаги), а соседи общего элемента всё равно не ехали.

**Где остаются события:** уведомления пульта (состояние, маркер, окончание); дискретные триггеры (`invoke goal` запускает сегмент); реакции внутри сцены — таблицей правил в описании канала, а не JS-колбэками: `'Scoreboard:goal' → 'Ticker: pause 3s'`. Таблицу видно в дампе и в `/schema`.

## 9.2. Внешние данные (M6)

Источники превращаются в сигналы: `source.ws(url)`, `source.json(path, { watch: true })`, `source.osc(port)`. Это данные для графики, а не управление: команды оператора идут только через API выше.

## 10. Инструменты агента

Это часть продукта, а не утилиты. CLI и MCP дают одни и те же операции.

| Операция | Результат |
|---|---|
| `render(entry, props, t)` | PNG одного кадра |
| `filmstrip(entry, props, from, to, n)` | Раскадровка одной картинкой + дамп на каждый кадр |
| `dump(entry, props, t)` | Текстовое дерево сцены (формат ниже) |
| `inspect(path, t)` | Геометрия, итоговые значения, provenance, фаза движения |
| `check(entry, props, range)` | Все нарушения `must` и встроенных правил за интервал |
| `diff(a, b, t)` | Разница двух версий: геометрия, значения, пиксельная маска. С M3b — внутри `keyfill test` (снапшот против текущей версии); отдельная команда отложена, см. «Статус M3b» |
| `perf(entry, range)` | Время кадра по стадиям, бюджет |

Формат дампа:

```
LowerThird#1  (96,904 640×88)  t=0.31s  presence=in 78%
├─ Dot#dot    (120,940 16×16)  opacity 0.62 ← loop:pulse
└─ Text#title "Анна Смирнова" (152,920 560×56)  Inter 600 48px (fit 56→48)  ✓ titleSafe
```

Структурная ошибка:

```json
{
  "rule": "must.fit",
  "node": "LowerThird#1/title",
  "source": "src/LowerThird.tsx:14:7",
  "frame": 19, "t": 0.316,
  "detail": { "content": [612, 56], "box": [560, 56] },
  "hint": "Добавь fit={{ shrinkTo }} или else=[{ shrinkTo: 40 }]; без них текст переполняет блок на 52 единицы."
}
```

Встроенные проверки помимо `must`: текст обрезан без явного разрешения, узел вне кадра на протяжении всего `in`, превышен бюджет кадра, неиспользуемые имена в таймлайне, анимация непрерывного свойства со скачком (разрыв значения между кадрами).

### CLI как контракт (веха M3)

CLI — продуктовая поверхность, а не обёртка для отладки: им пользуется агент, и всё, что он видит, должно быть дешёвым по токенам и однозначным. Решения ниже приняты до M3; M2 держит CLI минимальным, но совместимым с ними.

1. **Вывод.** По умолчанию компактный текст. У каждой команды есть `--json` со схемой версии `"keyfill": 1`. MCP отдаёт те же структуры, а текст строится из той же структуры, поэтому расходиться они не могут.
2. **Время** — одна грамматика для `--t`, `--cue` и MCP: `1.2` — секунды, `60f` — кадры, `settled` — конец `in`, маркеры (`out`, `stats`) и смещения (`out+0.2`, `stats-5f`), диапазоны `0..4` или имя сегмента (`in`, `loop`) — для `check` и `filmstrip`. С M2a работают секунды, кадры, `settled`, смещения и диапазоны в `filmstrip`; с M2b — маркеры таймлайна; с M3a — сегменты и диапазоны для `check` и `video`.
3. **Данные сцены.** Схема пропсов на уровне сцены: `defineScene({ props: { name: String, ... }, defaults: { name: 'Анна' }, root: (p) => ... })`; пропс без значения по умолчанию обязателен. В CLI — `--props data.json` или `--set name="Иван"` с проверкой типов по схеме. Это те же данные шаблона для пульта и `/schema`, и `update` в сценарии адресует их же.
4. **Скорость.** Операции живут в одном слое, которым пользуются CLI, `keyfill serve` и MCP. Бандл кэшируется по хэшу входных файлов в `.keyfill/cache`. Отдельного watch-демона нет: долгоживущий процесс появится вместе с `serve` и MCP.
5. **Тесты** — файлы `*.keyfill.test.ts`: `test('длинное имя', { scene, props, t: ['settled', 'out+0.1'], expect: { clean: true, snapshot: 'dump' } })`. tsc проверяет пропсы; снапшоты лежат рядом и обновляются `--update`; пиксели сравниваются с эталонным PNG с допуском. С M3b; маркеры в `t` tsc пока не проверяет (см. «Статус M3b»).
6. **Поставка.** Сейчас npm: `npm i -D @keyfill/cli` ставит `@keyfill/core` (типы, рантайм, бандлер), esbuild и нативный бинарь под платформу (как у esbuild и biome), запуск `npx keyfill`. С M3c. Потом `keyfill build` собирает `.keyfill`-пакет, который `keyfill serve` запускает без node.
7. **Конфиг** — `keyfill.config.ts` с типами: подложка и режим по умолчанию, каталог вывода, именованные сцены (`keyfill render lower`). Флаги перекрывают конфиг. С M3b; профили выходов (1080p50, 4K) — вместе с живыми выходами в M6.
8. **Справка.** `keyfill docs <тема>` и `keyfill explain <rule>` встроены в бинарь и совпадают с его версией; тест проверяет, что у каждого правила диагностики есть `explain`.

Ещё в контракте:

- Всё, что видит агент, — диагностики: ошибки сборки (`build.*` с `file:line`), исключения JS (`js.exception`, через sourcemap на строки TSX, а не бандла), нарушения `must`.
- Вывод подсказывает следующий шаг готовой командой (`keyfill inspect LowerThird#1/title --t 0.4`) и строкой для воспроизведения.
- Коды выхода: 0 — успех, 1 — ошибки в диагностиках, 2 — неверный вызов, 3 — сборка, 4 — исключение JS, 5 — сбой keyfill. Работают с M2a.
- Фильтры дампа `--path X`, `--depth N`; после `render` — краткое резюме.
- Команды. Увидеть: `render`, `filmstrip`, `video`, `dump`, `inspect` (`diff` — внутри `test`). Проверить: `check [--range]`, `test`, `perf`. Понять: `schema` (пропсы, части, команды, маркеры), `explain`, `docs`. Создать: `new <имя> [--template]`, `fonts`. Запустить: `preview` (окно), `serve`, `mcp`. Обслужить: `doctor` (node, esbuild, ffmpeg, конфиг), `cache clean`.
- Общие флаги команд, которые строят кадр: `--t`, `--props`/`--set`, `--mode`, `--bg`, `--seed`, `--scale`, `--json`. Вход — сцена, `*.cues.ts`, канал (`defineChannel`) или журнал канала `*.journal.jsonl` (с M4a).

## 11. Выходы

`Sink` получает кадр и метку времени. С M2c есть `keyfill video`: кадры диапазона уходят в ffmpeg через stdin, кодек выбирается по расширению или `--codec`:

| Кодек | Файл | Альфа | Для чего |
|---|---|---|---|
| ProRes 4444 (`prores`) | `.mov` | да | эфир, монтаж; по умолчанию |
| QuickTime Animation (`qtrle`) | `.mov` | да | без потерь |
| VP9 (`vp9`) | `.webm` | да | смотреть в браузере и в `keyfill view` |
| H.264 (`h264`) | `.mp4` | нет, кадры на подложке `--bg` | превью, мессенджеры |
| PNG (`png`) | каталог | да | без ffmpeg, покадрово |

Контейнер пишется с флагами bitexact: два прогона одной сцены дают одинаковые байты, это проверяет тест. Дальше — окно (winit), NDI, Spout (Windows), DeckLink (fill + key).

### Рендер: display list и бэкенды

Между кадром ядра и пикселями появляется явный **display list** — плоский список команд: залить или обвести скруглённый прямоугольник, тень с блюром, прогон глифов, трансформация, `push`/`pop` слоя с прозрачностью или клипом. Ядро строит его из кадра один раз; бэкенд только исполняет команды и ничего не знает о дереве, стилях и тексте. Вводится в M2, потому что тот же список нужен для `filmstrip`, сравнения кадров и кэширования неизменившихся слоёв в анимации.

Бэкенды:

- **CPU (`vello_cpu`)** — эталон. На нём золотые тесты и рендер в файл, где нужна побайтная воспроизводимость, и он же работает на серверах без GPU. CPU-путь не удаляется после появления GPU.
- **GPU (M8)** — второй исполнитель того же списка. Проверяется против CPU с допуском, потому что разные GPU и драйверы дают чуть разные пиксели. Обратная связь агента (дамп, `inspect`, `check`) от бэкенда не зависит.

Что меняет GPU кроме скорости растеризации:

- Видеовыходы получают байты, поэтому кадр читается из GPU асинхронно через кольцо из 2–3 буферов: плюс 1–2 кадра задержки, 4K RGBA — около 33 МБ на кадр. Окно и Spout забирают текстуру напрямую, без копий.
- Эффекты (размытие фона, свечение, свои шейдеры) делаются отдельными проходами на wgpu. На CPU у эффекта либо своя реализация, либо запасной вид — тем же механизмом, что `else`, и дамп честно говорит, что применено.
- Видео внутри сцены декодируется аппаратно сразу в текстуры; для тяжёлых сцен с видео GPU становится обязательным.

### Статус M0 (2026-10-16): готово

Работает сквозной путь `keyfill render|dump|inspect|check <scene.tsx>`: esbuild (dev-JSX) → QuickJS → дерево → `look` с provenance → Taffy → parley → vello_cpu → PNG с альфой, масштаб `--scale 2` для 4K. Золотой дамп `examples/lower-third/scene.dump.txt` проверяется тестом, заодно тест проверяет, что два прогона дают одинаковый дамп.

Отличия от плана выше, принятые по ходу:

- Мост в M0 — JSON-массив команд за кадр, а не бинарный буфер. Формат команд тот же, бинарная упаковка — когда появится профиль.
- `component()` требует `name`: без него экземпляр не назвать `LowerThird#1` в дампе и ошибках.
- Реализация `@keyfill/core` (`packages/core`) пока типизирована рыхло; контракт — `spec/keyfill.d.ts`. Сверка реализации со спекой — в M1.

Объявлено, но не исполняется (дамп помечает это прямо в строке узла): `presence`, `transition`, `timeline` (M2); `must`, `else`, `fit`, `anchor` вне верхнего уровня, `grid`/`stack`, `Span`, `Image`, `Shape`, градиенты, шрифты из файлов (M1).

Известные пробелы, которые закрывает M1:

- Текст, который не помещается в контейнер, тихо вылезает за него — это работа `must fit`.
- Снапшот дампа зависит от системных шрифтов (в примере Inter нет, берётся Arial и выдаётся `font.fallback`). Шрифты из файлов уберут эту зависимость.

### Статус M1 (2026-10-16): готово

- `must` (`fit`, `inside`, `contrast`, `visible`) и независимые варианты `else` в режимах dev/air, флаг `--mode`.
- `fit` с подбором кегля, переносом на `lines` строк, многоточием и обрезкой.
- Шрифты подключаются импортом (`import inter from '…/Inter-Regular.otf'`), `systemFonts: false`; Inter (OFL) лежит в `assets/fonts/inter`, примеры не зависят от машины. Сборку сцены делает `packages/core/bundle.mjs` (esbuild JS API с плагином, который превращает импорт шрифта в абсолютный путь).
- `Span` внутри `Text`: свой стиль на диапазоне, `case` на уровне Span, отдельный provenance в `inspect`.
- `grid` с дорожками и `cell`, `stack` с выравниванием по якорю, якоря внутри контейнеров и к частям компонентов.
- Реализация `@keyfill/core` типизирована типами спецификации; `packages/core/src/conformance.ts` проверяет каждый экспорт спеки (36 штук), и tsc падает при расхождении.
- Чтение сигнала в теле `view` или `scene.root` вне реактивного контекста ловится рантаймом: предупреждение `signal.untracked` с адресом экземпляра и местом в исходнике. Явное `untrack()` его глушит.
- Тесты: снапшоты дампов двух примеров, overflow в dev/air, `signal.untracked`, юнит-тесты `fit`, контраста и разбора значений.

Остаётся за рамками M1: `Image`, `Shape`, градиенты (рисуются первым стопом), режимы наложения; `presence`, `transition`, `timeline` — M2.

### Статус M2a (2026-10-16): готово

- JS-хост живёт всю сессию; ядро вызывает его только на командах сценария. Пропсы экземпляра — ячейки: `update` заменяет значение, эффекты пересчитываются, ядро видит изменения.
- `motion.rs`: изинги (cubic-bezier, пружины в замкнутой форме с передачей скорости), программы `animate`/`seq`/`par`/`delay`/`pulse`, дорожки каналов, жизненный цикл сцены и узлов. Правила — в разделе 8 «Как исполняется».
- Display list (`display.rs`) между кадром и бэкендом; `keyfill-render` только исполняет его. Раскадровка собирается на уровне списка: кадры вставляются со своим масштабом, подписи набираются шрифтом сцены, под прозрачностью — шахматка.
- Дамп показывает время, фазу сцены, журнал команд, фазу каждого узла (`[in 22%]`, `[loop]`, `[out 50%]`, `[transition background 25%]`) и слой presence (`motion opacity×0.5 · сдвиг -12,0`); `inspect` — каждый канал с источником, изингом и прогрессом.
- Тесты: золотой дамп сценария плашки в восьми моментах; кадр не зависит от пути к нему (дамп и PNG совпадают); stop посреди in продолжает с текущих значений; `update` запускает переход и уход по `when`; юнит-тесты кривых, пружин, программ, прерываний и pulse.

Известные пробелы:

- Раскладка не анимируется: когда узел уходит из потока, соседи сдвигаются скачком (видно в дампе плашки на 1.8 с). Это анимация геометрии из M5. *Закрыто в M5a: `transition.layout`.*
- `border`, `shadow`, `padding` переходами не анимируются; `blur` в `animate` пропускается с предупреждением.
- В дампе у идущего перехода показан токен цели, а промежуточный цвет — в `inspect`.
- `check` смотрит один момент; проверка за интервал (`check --t 0..4`) — в M3 вместе с остальным контрактом CLI.

### Статус M2b (2026-10-16): готово

- `timeline.rs`: разбор таймлайна (ключи, маркеры, `loop` repeat/pingpong/count, `holds`, `emit`) с проверкой имён маркеров и частей; воспроизведение экземпляра как кусочно-линейное отображение t → τ; hold, цикл, `next`, `stop` с прыжком на `out`, сегменты команд с возвратом; прыжки продолжают каналы с текущих значений.
- Сцена: `defineScene({ timelines })`, у каждого экземпляра своё воспроизведение; слой таймлайна складывается с presence.
- Сценарий: `next`; `play`/`stop`/`next` с компонентом — только его экземпляры (экземпляр снимается целиком после последнего out); `invoke` вызывает команду компонента. Короткая форма: `--cue "1.2 next; 4 stop Scoreboard"`.
- Команды компонента с типизированными параметрами; `ctx.set/play/next/stop/emit`. Команды движения из JS исполняются в момент команды сценария.
- События с точными моментами (`state`, `marker`, `emit`, `ignored`) в журнале сессии; дамп показывает последние к кадру, корень экземпляра — `[timeline loop τ=1.8]`, `inspect` — каналы слоя `timeline`.
- `--t` понимает маркеры: `--t goalHome+0.1`, `filmstrip --t ready..out`.
- Пример: табло с таймлайном (`Scoreboard.motion.ts`), командой `goal` и эфирным сценарием `scene.cues.ts`. Неподключённый `LowerThird.motion.ts` удалён: плашка остаётся примером presence и transition.
- Тесты: сценарий «play → hold → next → stop посреди in» с точным списком событий и плавным out; `goal` меняет счёт, играет сегмент и возвращает в цикл; маркер в грамматике времени; золотой дамп эфирного сценария табло; юнит-тесты воспроизведения (hold, pingpong, выход из цикла, stop посреди in, сегмент с возвратом).

Известные пробелы:

- Пружина в таймлайне может перелетать: `opacity×1.02` в дампе — честное значение, рендер обрезает прозрачность до 1.
- Прыжок не передаёт скорость пружины: каналы продолжают с текущего значения, но с нулевой скоростью.
- События пока живут только в журнале сессии; клиенты управления получат их в M4.

### Статус M2c (2026-10-16): готово — M2 закрыта

- `stagger(step, motion, { reverse })`: каскад на детях узла в presence; длительность `in` включает весь каскад.
- `count()` и `clock()` (`dynamic.rs`): куски текста, которые ведёт ядро; формат чисел и часов, пауза, сброс, обратный отсчёт. В примерах: счёт табло через `count`, матчевое время через `clock`, каскад имени и должности в плашке.
- `keyfill video`: ProRes 4444 / QuickTime Animation / VP9 с альфой, H.264 на подложке, PNG-последовательность; premultiplied → прямая альфа перед ffmpeg. 231 кадр 1080p табло — около 3 с в release. Проверка плана M2 выполнена: видео с альфой побайтно одинаковое при двух прогонах (ProRes и VP9).
- `keyfill view [entry] [--dir out] [--port 4747]`: сервер на std::net, только loopback (IPv4 и IPv6). Галерея файлов каталога с автообновлением (картинки, WebM/MP4 на шахматке, текст, HTML). Живая сцена: ползунок времени, кадр по запросу, маркеры и команды сценария на шкале, воспроизведение, подложки (альфа, чёрная, хромакей), дамп с кликабельными узлами, подсветка рамки узла под курсором и выбранного узла (рамки считает ядро — `display::node_boxes` — с учётом движения), `inspect` по клику в кадре, журнал событий. Правка исходников рядом со сценой пересобирает её и обновляет страницу.
- Тесты: каскад, `count`/`clock` по времени, побайтность видео, форматы чисел и часов, прямая альфа, разбор URL.

Известные пробелы:

- Воспроизведение в `keyfill view` — кадры по запросу. Цикл на rAF запрашивает кадр только при смене номера кадра сцены. До двух запросов в полёте, декодирование через `createImageBitmap`, отрисовка в canvas; дамп обновляется на паузе. На табло 1080p (половинное качество) — 50 кадров/с, около 7 мс на кадр. Сервер слушает и IPv4, и IPv6 loopback: иначе `localhost` на Windows добавлял 200 мс к каждому запросу. Тяжёлым сценам плавности может не хватить; тогда `keyfill video … -o out/x.webm`, галерея играет его сама.
- ProRes и QuickTime браузер не воспроизводит; галерея показывает подсказку.

### Статус M3a (2026-10-16): готово

- `ops.rs` — один слой операций: render, dump, inspect, check, filmstrip, video, schema. Каждая возвращает структуру; текст строится из неё же (`output.rs`), поэтому `--json` и текст не расходятся. Дамп и inspect в ядре стали структурами (`dump::build`, `dump::inspect_build`); старый текст получается из них без изменений, золотые дампы совпали.
- Конверт `--json`: `{ keyfill: 1, command, ok, exit, entry, at, result, logs, next, repro }`, ошибка — `{ ..., ok: false, error: { kind: usage|build|js|internal, message, diagnostics } }`. Числа округлены до сотых, как в тексте; ключи идут в порядке структуры (`serde_json` с `preserve_order`, поэтому `must` в дампе теперь в порядке исходника).
- `check` проверяет каждый кадр диапазона (по умолчанию — весь сценарий) и сводит нарушения: одна запись на правило, узел и место, с первым и последним кадром и числом кадров. Весь сценарий табло (231 кадр) — около секунды в debug.
- Время: там, где нужен диапазон, имя — сегмент: `in` (от play до settled), маркер таймлайна (до следующего маркера; сегмент команды, который до него не доходит, — по длине на таймлайне), `out` без маркера (от stop до конца).
- Пропсы сцены: схема как у компонентов плюс `defaults`; `--props data.json`, `--set name=…` с приведением по схеме; ошибка данных — код 2 со списком известных пропсов и подсказкой `keyfill schema`. В сценарии `at(t, 'update', { ... })` без компонента меняет пропсы сцены; tsc проверяет имена и типы, а у сцены без пропсов такой `update` — ошибка типов.
- `keyfill schema`: пропсы сцены, компоненты (пропсы, части, команды с параметрами, экземпляры), маркеры, holds и цикл таймлайнов, команды сценария.
- Бандлер отдаёт JSON с кодом, sourcemap и списком входных файлов. Кэш `.keyfill/cache` по содержимому входов, версии keyfill и `bundle.mjs`: повторный запуск — около 35 мс вместо 90.
- Исключение JS — диагностика `js.exception`: стек переведён через sourcemap на строки TSX, кадры `@keyfill/core` свёрнуты. Ошибка сборки — `build.syntax` / `build.resolve` с `file:line:col` и строкой кода в `detail`.
- `next` подсказывает готовую команду (`keyfill inspect <сцена> <узел> --t <первый кадр ошибки>`), `repro` воспроизводит вызов с разрешённым временем.
- Тесты: `tests/cli.rs` запускает бинарь с `--json` и проверяет конверт, коды выхода 2/3/4, пропсы, schema, сегменты, фильтры дампа, стек через sourcemap; юнит-тест VLQ; контракт tsc для пропсов сцены.

Известные пробелы:

- Диагностики сборки — только синтаксис и разрешение импортов: типы TS проверяет `tsc`, keyfill его не запускает.
- Кэш хранит последнюю сборку каждой сцены: откат правки пересобирает бандл.

### Чистка после M3a (2026-10-16)

По ревью всего проекта (повторы, упрощение, эффективность, уровень исправлений), без смены поведения, кроме отмеченного:

- **Ошибки типизированы там, где возникают.** `Failure::Usage(текст) | Props(ошибки) | Build(диагностики)` и `JsException` с полями (сообщение, место, кадры стека, скрытые кадры `@keyfill/core`). Код выхода и `error.kind` берутся из типа; текст ошибок больше не разбирается. Разбор вызова в `main.rs` отделён от исполнения: любая ошибка флагов — код 2, в том числе `--scale 0` и `--n 0`, которые раньше давали 5.
- **Сессия перематывается сама.** Запрос момента раньше текущего перезапускает её с начала, поэтому операции обходятся одной сессией: момент и диапазон разрешаются на той же сессии, что строит кадры. Просмотрщик больше не держит свою логику переиспользования и выбрасывает сессию после ошибки.
- **Операции возвращают `Outcome`**: результат, момент или диапазон, флаг ошибок и узел для подсказки `keyfill inspect`. Подсказка предлагается только для узла, который есть в сцене.
- **Таймлайны разбираются один раз** при монтировании (`Scene::timelines: Vec<TimelineDef>`); `schema` и сегменты времени читают те же определения, `schema` показывает и неявный цикл `loop..out`.
- **Состояния — enum, а не строки**: фазы узла (`Note`: in/out с прогрессом, transition, timeline с τ и маркером), причина ухода узла (`Gone`: после out, адресный stop, снят таймлайном), состояние воспроизведения (`RunState`), фаза сцены, команды сценария (`CueCmd`) и движения (`MotionAction`). В JSON фазы — структуры вместо строк вида `"in 78%"`; дамп снятого экземпляра называет настоящую причину.
- **Числа в JSON точные.** Округляется до сотых только геометрия f32 там, где строится дамп; время, данные сцены и значения по умолчанию в `schema` отдаются как есть. Результат пишется напрямую (`RawValue`), без промежуточного `Value`.
- **Просмотрщик** получает строки дампа с адресами узлов (`dump::lines`), а не разбирает псевдографику дерева; правки отслеживаются по входным файлам бандла; лишний `/api/hit` удалён.
- **Скорость** (табло, release): рендерер с состоянием (`keyfill_render::Renderer`: контекст, кэш глифов и буфер кадра живут между кадрами), быстрое сжатие PNG для просмотрщика и PNG-кадров, кэш шейпинга текста в `TextEngine`, подсказка `else` считается один раз на узел и нарушение, метки событий не форматируются в `check` и видео, VP9 и H.264 кодируют в 8 потоков с фиксированными тайлами (байты одинаковые на любой машине). `check` 109 → 71 мс, `check` сцены с нарушением на 501 кадре 162 → 106 мс, webm 6,3 → 3,6 с, PNG-последовательность 3,4 → 1,2 с, кадр в просмотрщике ~7 → ~3 мс.
- **Общие помощники вместо копий**: `Rgba::from_hex`, `diag::Counts`, `Session::frame_index/frames`, `Transform::default`, `Frame::safe_area`, `Display` для `Rect`, общие ячейки пропсов компонента и сцены в `@keyfill/core`; удалён мёртвый код.

### Критическое ревью всего проекта (2026-10-16)

Исправлено (регрессии — `crates/keyfill-cli/tests/regressions.rs`, сцены — `tests/fixtures/review`):

- **Детерминизм JS.** `Date` подменён целиком: конструктор без аргументов и `Date()` дают `--now`, часовой пояс — UTC на любой машине (локальные геттеры и сеттеры равны UTC-шным, строка без пояса разбирается как UTC). Раньше `new Date()` давал реальное время, и видео расходилось между запусками.
- **Лимит на JS**: монтирование и каждая команда сценария не дольше 10 с (`RunOptions::budget`); бесконечный цикл даёт `js.exception` с подсказкой, а не вешает CLI и просмотрщик.
- **Таймлайн.** После сегмента команды (`ctx.play(marker)`) в pingpong-цикле каналы снова идут по ключам. Ранний `next`, пока цикл не начался, — событие `ignored`, а не молчаливая отмена цикла. Остановка на `out` не считается его прохождением: `--t out` и сегмент `out` — момент `stop`. Границы витков на сетке 1e-9 с: кадр на границе всегда показывает начало нового витка. Дробный `loop.count` — ошибка разбора.
- **Движение.** Узел, появившийся снова, начинает с объявленных значений (дорожки прошлого `out` сбрасываются). Время успокоения медленной пружины считается дальше 10 с по огибающей, без скачка; дольше 10 с — предупреждение `motion.spring-slow`. Второй `stop` во время ухода — `ignored`. Неанимируемый канал (`blur`) в ключе таймлайна пропускается с `motion.unsupported`, а не выбрасывает таймлайн.
- **`must` не видит слой движения**: каналы `abs`, которые сейчас ведут presence или таймлайн (ширина посреди появления), в проверке не участвуют — кадр рисуется с ними, проверяется без них. В air-режиме `else` больше не срабатывает посреди появления.
- **`keyfill view`.** Файлы галереи — только имя внутри `--dir` (раньше `/files/C:Cargo.toml` отдавал файлы рабочего каталога). Запросы с чужим `Host` — 403 (защита от DNS rebinding). Запрос читается в потоке соединения с таймаутом 2 с: молчащий сокет больше не вешает сервер. `Range: bytes=-N`.
- **CLI.** Кэш бандла не пишется, если вход изменён во время сборки. `-o` в несуществующий каталог — код 2. Вывод в закрытый stdout (`| head`) не паникует. `--t` с маркером или `settled` округляется к кадру вверх: кадр не раньше события.

Отложено (не мешает текущей работе, вернуться при случае):

- `on()` в шагах `else` вычисляется один раз и не реактивен (`index.ts`, `createNode`).
- `when` на компоненте и на корне его view пишут `hidden` двумя эффектами: побеждает сработавший последним.
- Ошибка посреди `keyfill video` оставляет обрезанный файл; нечётный размер кадра для yuv420 (`--scale`) даёт сырую ошибку ffmpeg.
- Задачи Promise (`.then`) в сцене не исполняются, и об этом нет диагностики; `Intl` и локали не зафиксированы.
- Кэш бандла не видит `tsconfig`/`package.json` и новые файлы, которые меняют разрешение импортов.
- Границы диапазонов `check`/`filmstrip` из маркеров округляются к ближайшему кадру, а не вверх.

### Статус M3b (2026-10-16): готово

- **`keyfill explain [правило]` и `keyfill docs [тема]`** встроены в бинарь: тексты лежат в `crates/keyfill-cli/help` (`rules.md` — раздел на правило, `docs/*.md` — темы: start, cli, time, scene, cues, look, layout, must, motion, timeline, test, config, perf). Тест `every_rule_has_explain` ищет правила в исходниках (`crates/*/src`, `packages/core/src`) и сверяет с `rules.md` в обе стороны: правило без объяснения и объяснение без правила — ошибка. Правила `unsupported` и `m0.unsupported` переименованы в `render.unsupported` и `look.unsupported`. `next` к первой ошибке предлагает `keyfill explain <правило>`.
- **Точка входа бандла — `__keyfill_main`** из `@keyfill/core`: файл может быть сценой, сценарием, файлом тестов или `keyfill.config.ts`. Что делать, говорит ядро (`RunOptions::entry`: сцена, список случаев теста, случай с номером).
- **`keyfill.config.ts`** (`defineConfig`): `mode`, `bg`, `seed`, `now`, `out`, `scenes`; ищется вверх от каталога запуска, собирается и исполняется как сцена (бандл кэшируется), неизвестный ключ — код 2. С `out` файл по умолчанию повторяет путь сцены (`out/examples/lower-third/scene.png`), без него — рядом со сценой, как раньше. Имя сцены годится вместо пути. Конверт `--json` называет конфиг полем `config`. В репозитории — `keyfill.config.ts` с `out: 'out'` и сценами `lower`, `score`.
- **`keyfill test`** (`suite.rs`): случай — сцена или сценарий, `props` (tsc сверяет со схемой: `Cues` стал обобщённым по пропсам сцены), моменты `t`, `mode`, `bg`, `scale`, `expect: { clean, snapshot, tolerance }`. Бандл файла собирается один раз; каждый случай монтирует свою сцену и дальше идёт обычными операциями (`ops::frame`, `ops::check`), поэтому тест видит ровно то, что `dump` и `check`. Диапазон в `t` проверяется на `clean` по всем кадрам.
  - Снапшоты — `__snapshots__/<файл>/<случай>@<t>.dump.txt|.png` рядом с тестом, в git (`.gitignore` пропускает их PNG). Нет файла — пишется; расходится — случай падает; `--update` перезаписывает и при полном прогоне удаляет снапшоты удалённых случаев.
  - Дамп в снапшоте без мест в исходнике: вставка строки кода не меняет снапшот. Разница — по узлам, а не по строкам: узлы сопоставляются по адресу (`+` появился, `-` пропал, `~` изменился, со старой и новой строкой).
  - Пиксели — эталонный PNG и допуск (`channel` 2 из 255, доля `pixels` 0,001); при расхождении новый кадр и маска отличий пишутся в `.keyfill/test`, в отчёте — число отличий и их рамка.
  - Ошибка одного момента (неизвестный маркер) не останавливает остальные; ошибка данных или JS — весь случай. `keyfill test` идёт из каталога конфига: пути в дампах от него. Подсказки: `keyfill test <файл> --update`, `keyfill explain <правило>`.
  - Примеры: `examples/*/…keyfill.test.ts` (дамп и пиксели плашки, длинное имя, сценарии, переполнение в dev и air). Тест длинного имени сразу нашёл дефект примера: у края titleSafe точка «в эфире» сжималась до 12×16 — теперь у неё `shrink={0}`.
- **`keyfill perf`**: на каждом кадре диапазона время стадий `script` (команды и JS), `motion`, `layout` (раскладка, текст, `must`), `raster` и кадра целиком — mean, p50, p95, max, число кадров дольше `1/fps`, самые долгие кадры, время запуска сцены, тип сборки. p95 кадра больше бюджета — warn `perf.budget` с самой дорогой стадией (код 0: замер зависит от машины). Табло в release: кадр p95 ≈ 0,9 мс при бюджете 20 мс, почти всё — raster.
- Тесты: контракт CLI (explain, docs, конфиг и именованные сцены, `keyfill test` по примерам без новых снапшотов и по фикстуре с четырьмя упавшими случаями, perf, неверный конфиг), юнит-тесты разницы дампов, сравнения пикселей, имён файлов и PNG; контракт tsc для `test` и `defineConfig`.

Решения и пробелы:

- **`keyfill diff` отдельной командой не сделан.** Его сценарий («что ещё изменила моя правка») закрывают снапшоты `keyfill test`; сравнение с git-ревизией (`--base HEAD`) — отдельная механика ради редкого случая. Вернуться, если агенту понадобится сравнивать сцены без тестов.
- tsc не проверяет маркеры в `t` тестов: у `SceneDef` нет типов маркеров его таймлайнов. Неизвестный маркер — ошибка этого момента, маркеры сцены — `keyfill schema`.
- Снапшот PNG зависит от растеризации: на другой платформе возможны отличия сглаживания в пределах допуска; при больших — поднять `tolerance` у случая.
- `perf` меряет CPU-бэкенд и не включает кодирование видео и вывод.

### Статус M4a (2026-10-16): готово

- **Типы пропсов в рантайме** (`packages/core/src/props.ts`): `prop.string`, `prop.number({ min, max, int })`, `prop.boolean`, `prop.enum([...])`, `prop.list(item, { min, max })`, `prop.object({...})`, `prop.image()`, `prop.json<T>()`, у всех `default` и `description`; `String`, `Number`, `Boolean` — короткая запись. Одно описание даёт три вещи:
  - TS-тип: `PropType<T, D, I>` несёт значение внутри компонента, наличие `default` и тип снаружи; у компонента появился тип входных пропсов (`Component<P, N, C, I>`), пропсы и поля объектов с `default` снаружи необязательны;
  - JSON Schema в `PropInfo.schema` (у пропсов сцены, компонентов и параметров команд) и короткую подпись типа (`integer 0..`, `enum home|away`, `list<string>`) для текста `keyfill schema`; картинка — `"x-keyfill": "image"`, json — `"x-keyfill": "json"`;
  - проверку значений с путём в ошибке (`players[1].number: ожидается число ≥ 0, получено -1`): `--props`/`--set` (строки приводятся по типу), `update` и `invoke` сценария, начальные значения в JSX (аксессоры не проверяются — их проверил tsc), команды канала. `update` проверяет все значения и применяет их вместе, только если ошибок нет.
  - Голый `prop<T>()` убран (ломающее изменение в alpha): тип без рантайм-описания пульту бесполезен; запасной выход — явный `prop.json<T>()`.
- **Канал** (`defineChannel`, `examples/channel`): пустой stage, каталог компонентов, экземпляры по командам `load`, `play`, `next`, `stop`, `update`, `invoke`, `clear`. Слоями и порядком ведает ядро (`Session::command` в `crates/keyfill-cli/src/session.rs`); JS-сторона (`__keyfill_channel`) только монтирует, меняет данные, исполняет команды и снимает экземпляры:
  - экземпляр — корень под stage; порядок детей stage равен порядку слоёв (`insert` с `before`); на своём слое новый — поверх уходящего;
  - загруженный (`load`) не виден, пока его не покажет `play` (`Gone::Loaded`, в дампе «загружен на слой, ждёт play»);
  - после `stop` и конца `out` экземпляр удаляется целиком: узлы (`remove`), состояние движения и таймлайна (`MotionState::forget`), эффекты JS (владелец эффектов `createRoot` в `signals.ts`). Событие `removed` — в момент конца ухода;
  - таймлайны строятся для каждого нового экземпляра, а не один раз при монтировании;
  - исключение в `view` при монтировании отбрасывает недостроенное дерево; отказ по пропсам не трогает даже счётчик имён экземпляров;
  - события слоёв в общем журнале событий: `loaded <слой>`, `playing`, `stopping`, `removed`, `ignored` (play на занятом слое, stop на пустом).
- **Журнал** (`crates/keyfill-cli/src/channel.rs`): `Journal::parse`/`to_jsonl`, ошибки разбора с номером строки, канал — путь от каталога журнала, сид и часы — из заголовка. Журнал — `<entry>` (`Job::new`, `keyfill view`); кадр по умолчанию — когда успокоилось то, что запустила последняя пачка. При воспроизведении отклонённая команда — error `channel.rejected`, расхождение с записью (`error` в журнале против успеха сейчас и наоборот) — error `journal.diverged`.
- **Снимок** — `State` (`Session::state`) и `State::to_batch`. Восстановленные экземпляры пока проигрывают `in` заново; вход сразу в «эфир» — в M4b вместе с подъёмом `serve`.
- `keyfill schema` у канала показывает каталог и пачки журнала; `keyfill docs props`, `keyfill docs channel`; `explain` для `channel.rejected` и `journal.diverged`.
- Тесты (`crates/keyfill-cli/tests/channel.rs`): живая сессия с командами между кадрами и её журнал, прочитанный из JSON Lines, совпадают по дампу и пикселям в 12 моментах; отказы с причинами и без следа; снимок с данными после `ctx.set`, загруженный экземпляр, восстановление, уход и удаление; упавшая в JS команда в журнале и её воспроизведение без расхождения, расхождение после правки; ошибки журнала, написанного руками; JSON Schema пропсов. CLI: журнал как `<entry>`, ошибки журнала с номером строки. Контракт tsc для `prop.*` и `defineChannel`.

### Статус M4a+ (2026-10-16): готово — списки по данным

- **`For`** (`packages/core/src/index.ts`, `ListRegion`): элементы — корни со своим владельцем эффектов (`createRoot`); корень внутри другого владельца (список в экземпляре канала) снимается и вместе с ним. Данные элемента — сигнал на ключ, место — сигнал индекса; функция элемента исполняется в `runView`, поэтому чтение вне аксессора ловит `signal.untracked`. Список вставляет элементы перед следующим ребёнком контейнера, так что статичные дети и несколько `For` в одном `Box` держат порядок.
- **«Уйти и удалиться» — операция ядра** (`release` в мосте, `Scene::released`, `MotionState::release`, `Session::sweep`): узел проигрывает своё `out` и таймлайн до маркера `out`, у узла без своего `out` — каскад `out` контейнера; когда уход кончился, сессия удаляет узлы и движение их забывает. Экземпляр канала после `stop` уходит этим же путём (JS снимает его эффекты сразу, узлы удаляет ядро), `clear` по-прежнему убирает сразу (`remove`).
- **Вход добавленного**: узлы, которые данные добавили в уже играющую сцену под существующий корень, входят сразу — своё `in`, без него — каскад `in` контейнера по порядку среди добавленных вместе; их таймлайны начинают воспроизведение. Новый корень под stage (экземпляр канала) по-прежнему ждёт своего play. Дети узла в движении обновляются при каждом наблюдении, поэтому каскад видит текущий порядок.
- Адреса по ключу (`Node::key`, `Scene::path`): `…/box[key=zen]`; ключевые элементы не входят в индексы соседей.
- `examples/standings`: таблица с данными сцены `teams` (`prop.list(prop.object(...), { max: 8 })`), сценарий тура (уход, вход, перестановка, смена очков) и тест со снапшотами, в том числе длинное название с `fit`.
- Тесты (`crates/keyfill-cli/tests/lists.rs`): строки по ключу — уход на своём месте, каскад на новой строке, тот же узел у того же ключа, удаление после ухода, перестановка; кадр не зависит от пути; повтор ключа и объекты без `by`; список внутри экземпляра канала — уход строк по данным, полное снятие экземпляра без остатка узлов. Контракт tsc для `For`.

Пробелы:

- Перестановка мгновенная: переезд строки на новое место — анимация геометрии (M5). Соседи уходящей строки сдвигаются скачком, когда она удалена. *Закрыто в M5a: `transition.layout` на строке.*
- Таймлайн не адресует элементы списка (части компонента статичны); движение элементов — `presence` и `stagger`, у элемента-компонента — его собственный таймлайн.
- Бегущей строки (бесконечная прокрутка элементов) нет — отдельный примитив поверх `For`.

### Статус M4b (2026-10-16): готово — keyfill serve

Решения пользователя: WebSocket на `tungstenite` (синхронный, без tokio; MIT/Apache); каналы — `channels` в `keyfill.config.ts` и аргументы (`keyfill serve a.tsx b.tsx` — каналы 1, 2), аргументы перекрывают конфиг; `/monitor` — PNG по запросу (поток MJPEG и NDI — с живыми выходами в M6); `--resume` — сразу «в эфир».

- **Устройство** (`crates/keyfill-cli/src/serve.rs`): у канала свой поток — он владеет сессией (QuickJS не делится между потоками), тикает по часам кадра (`Instant` от старта, отставание пропускает кадры, а не догоняет их) и на границе кадра применяет пришедшие команды; ответ клиенту — с номером кадра. Сетевые потоки отдают запросы в очередь канала (`Req`) и ждут ответ; события расходятся всем клиентам (`Hub`). HTTP разбирается общим с `keyfill view` кодом, WebSocket — рукопожатие своё, кадры — `tungstenite`.
- **Протокол** (`keyfill docs serve`): команды слоям как в журнале плюс `channel`, `to: program|preview`, `id`; `batch` — атомарная пачка; `take`, `discard`, `state`, `schema`. Ответ `ack` с `results` (`ok`/`rejected`/`failed`). Рассылка: `hello`, `event` (жизненный цикл, маркеры, emit — с моментом и кадром), `state` после каждой принятой пачки, `preview`, `diagnostic` (новая диагностика эфира — один раз, пока держится). HTTP: `/`, `/schema` (каталог и JSON Schema), `/state`, `/monitor/<N>.png?scale&preview`.
- **Preview** — снимок эфира (`State::to_batch`, сразу «в эфир») плюс отложенные команды на отдельной сессии; кадр — `Session::quiet_time` (улеглись in и уходы), с диагностиками air-режима. Отложенная команда сразу проверяется, отклонённая не попадает; эфир изменился — preview пересобирается; `take` — пачка в эфир на ближайшем кадре.
- **Журнал** пишется по ходу эфира (`Session::take_recorded`, строка на принятую пачку, `flush`): `ch<N>-<UTC>.journal.jsonl` в `--journal` (по умолчанию `.keyfill/journal`), канал в заголовке — путь от каталога журнала, часы JS (`now`) — момент запуска. Имя не перезаписывается (`-2`, `-3`).
- **«Сразу в эфир»**: `play` с `instant: true` (`MotionState::play_settled`) — тот же `in`, начатый раньше на свою длительность, таймлайн — от `t − settle_tau` до первой остановки (hold или цикл); события in и маркеров — в прошлом. `--resume` воспроизводит последний журнал канала до конца, берёт снимок и ставит его первой пачкой нового журнала.
- **Доступ**: по умолчанию `127.0.0.1` и проверка `Host` (DNS rebinding); `--host` не loopback — только с токеном (`--token`, `KEYFILL_TOKEN`): `Authorization: Bearer` или `?token=`, сравнение без раннего выхода.
- `keyfill.config.ts`: `channels`; режим serve по умолчанию — air.
- Тесты (`crates/keyfill-cli/tests/serve.rs`): настоящий процесс и WebSocket-клиент — команда в эфир с событиями, отказы, preview с картинкой, отличной от эфира, take, discard, журнал без отклонённых и с каналом от своего каталога, подъём `--resume` в состояние playing; токен вне loopback и его проверка.

Пробелы:

- Сверка «журнал serve в `render` = живые кадры» по пикселям — шаг M4c (кадры живого эфира пока не сохраняются).
- Журнал событий и пачек сессии растёт всю сессию эфира: для многочасовых эфиров нужна обрезка истории (снимок + хвост).
- Один клиент — один поток; на сотни пультов не рассчитано.

### Статус M4c (2026-10-16): готово — M4 закрыта

- **Проверка вехи** (`crates/keyfill-cli/tests/serve.rs`, `live_show_matches_its_journal`): настоящий `keyfill serve` и WebSocket-клиент играют эфир — табло, `next`, гол, плашка через preview и take, уход обоих одной пачкой. ### Статус M5d (2026-10-16): готово — место в состоянии, морфинг как композиция

Решение пользователя после обсуждения: «всё, что можно упростить, упрощать; сложность — в композиции, а не в деталях». Первая версия с `share` (общие элементы между разными компонентами: передача места, гашение `in` контейнеров, пропуск ключей таймлайна) работала, но была убрана как второй механизм тождества с особыми случаями.

- **Место экземпляра в состоянии**: `Component.with(props, { anchor })`, `to` — `stage`, `actionSafe`, `titleSafe` или `'слой:часть'`. JS при загрузке проверяет слой (есть, не свой) и что часть есть у компонентов целевого слоя; ядро получает якоря в `ChannelDef.anchors`. Сессия ставит якорь корню при монтировании и смене привязки (`place`), а без якоря в состоянии возвращает исходный из `view` (`Inst.own_anchor`); изменение идёт внутри `relayout`, поэтому корень с `transition.layout` едет к новому месту.
- **Якорь к части другого слоя**: цель `{ $part, layer }`; `Scene.layer_insts` (ведёт сессия перед каждой раскладкой) — какой экземпляр сейчас на слое: показанный, а пока он ждёт шага — уходящий. Узел ставится у видимой части (место и размер с анимацией геометрии), место в раскладке — у конечной. Корень с якорем к части ограничен кадром, а не размером части.
- **Пример** `examples/match/MatchCard.tsx`: одна подложка с обликами `intro` (названия по центру) и `score` (счёт и часы); `intro → live` — тот же экземпляр едет из центра в угол и меняет размер, содержимое сменяется. `Tag` в состоянии `var` стоит под подложкой карточки. Табло `Scoreboard` в канале матча больше не используется.
- Тесты (`tests/states.rs`): тот же экземпляр меняет облик и место (линейно, с точными рамками) и возвращается к своему якорю; якорь едет за растущей частью другого слоя (видимое место — за видимой частью, место в раскладке — за конечной).

Пробелы:

- Переход между двумя разными компонентами без общей оболочки не морфится — это осознанно; вернуться к явному шагу `morph()` в правиле перехода, если анализ эфира покажет реальную нужду.
- Текст не морфится: облик сменяется кроссфейдом содержимого.
- Переход узла в другой контейнер (из таблицы в выделение) не поддержан.
- Цепочки якорей к частям (якорь к части, которая сама привязана к части) по-прежнему не поддерживаются.
- Просмотрщик (`keyfill view`) на отладочной сборке отдаёт кадр 1080p за 80–240 мс, на релизной — 15–25 мс; каждый кадр он ещё раз строит для дампа и кодирует PNG. Для живого просмотра нужен отдельный путь (без дампа на каждом кадре, меньший масштаб) — к анализу после M5.

### Статус M5c (2026-10-16): готово — хореография переходов

Решения пользователя: по умолчанию `together()` (всё в момент команды, как в M5b); при прерывании неначатые шаги прежнего перехода отменяются.

- **Правила** (`packages/core/src/index.ts`, `compileTransitions`): `together()`, `sequence(gap)`, `overlap(seconds)` (= `sequence(−seconds)`), функция шагов `({ out, enter, update }) => [...]` с `after`/`with`/`at`/`offset`. Ключи `'a -> b'`, `*` — любое состояние; `default`. Проверка при загрузке: слои из `layers`, состояния из `states`; для пары двух названных состояний — по таблице состояний, что шаг и его якорь в этом переходе бывают; повтор шага; цикл зависимостей.
- **Расписание** (`crates/keyfill-core/src/transition.rs`): `pick` — правило для пары (точная, `from -> *`, `* -> to`, `* -> *`, `default`, `together`); `resolve` — начало каждого шага от начала перехода по длительностям, с пояснением («after lower:out −0.1»); якоря, которых в этом переходе нет (прерывание пересобрало разницу), и циклы — от начала, с пометкой; не раньше начала перехода. `TransitionPlan` — для дампа и JSON (`time.transition`).
- **Сессия**: `enter_state` → `diff_steps` (учёт слоёв сразу в цель: входящий смонтирован и ждёт, уходящий среди уходящих, но ещё на экране) → `durations` (те же `play`/`stop`/`revive` на копии `MotionState`, `in_end`/`hide_time`) → `resolve` → шаги с началом 0 исполняются сразу, остальные — в `pending` и исполняются в `advance` в свои точные моменты (до команды в тот же момент; с `relayout`). `cancel_pending` отменяет неначатые: невошедший снимается, неушедший возвращается, неразвёрнутый снова уходит. Экземпляр, назначенный к развороту, не снимается по концу прежнего `out`.
- **Конфликт** `transition.overlap` (warn): вход на одном слое начинается раньше конца ухода на другом, и прямоугольники корней пересекаются (раскладка с показанным входящим). Правило и объяснение — в `keyfill explain`.
- Preview (`quiet_time`) ждёт и конца расписания.
- Пример `examples/match`: `'pregame -> live': sequence(0.1)`, `'live -> interview'` — гость через 0.3 с после обновления табло.
- Тесты: юнит-тесты расписания и выбора правила; `tests/states.rs` — расписание и события по нему, диаграмма в кадре, отмена неначатых шагов, отложенный разворот, `transition.overlap` и `sequence()` без него, ошибки цикла и несуществующего шага, живой эфир матча = журнал.

Пробелы:

- Длительность `update` в расписании — ноль: `after: 'score:update'` = его начало. Длительность переходов `transition` при обновлении не учитывается.
- Якоря к маркерам таймлайна (`after: 'score:ready'`) не поддерживаются — только к шагам перехода.
- Конфликт проверяется по прямоугольникам корней экземпляров, а не по видимым частям; корень без якоря (во весь stage) пересечётся со всем.

### Статус M5b (2026-10-16): готово — состояния канала

Решения пользователя: данные — у канала (`props`, `update` без слоя), состояния — привязки компонентов к ним (`states: (d) => ({ live: { score: Scoreboard.with({ homeScore: d.homeScore }) } })`); уходящая плашка, которая снова нужна, разворачивается (не новая копия); на слоях состояний работают только `invoke` и `next`.

- **JS** (`packages/core/src/index.ts`): `Component.with(props)`; данные канала — ячейки пропсов, как у сцены; таблица состояний строится один раз при загрузке канала, и каждая привязка проверяется по схеме компонента (ошибка канала с состоянием и слоем). Операции канала: `mount` с `state`/`layer` (пропсы из привязки — аксессоры данных), `bind` (тот же экземпляр переходит на привязку нового состояния, недостающие пропсы — из `default`), `data` (проверка, обновление, ответ `data` и текущие пропсы всех экземпляров).
- **Ядро/CLI**: `scene::ChannelDef` (каталог, слои, состояния, схема и начальные данные); команды `state {name, instant}` и `update` без слоя; `Session::enter_state` — разница по слоям состояний в порядке номеров; `park` — уход экземпляра состояния без `release`: в JS он жив до конца `out`, снимает его `sweep` (JS `unmount`); `show_state` разворачивает уходящий того же компонента (`MotionState::revive`: узлы посреди `out` играют `in` с текущего места, ушедшие — с объявленных, таймлайн заново) или монтирует новый.
- **Снимок**: `State.state`, `State.data`; `to_batch` — `update` данных, `state <имя>` instant, потом свободные слои. Preview, `--resume` и `/state` работают без изменений протокола; `/schema` и `keyfill schema` показывают слои, состояния и данные.
- **Протокол serve**: `state` с `name` — переход, без `name` — снимок, как раньше.
- Пример `examples/match` (канал с четырьмя состояниями и журнал эфира).
- Тесты (`tests/states.rs`, `tests/serve.rs`): разница состояний и тот же экземпляр табло, данные в привязках, отказы с подсказками, `invoke`/`next` на слое состояний, `clear` всего канала, разворот уходящей плашки без копии, снимок и восстановление, живой эфир матча = журнал (дамп и пиксели), ошибка неисправимой привязки, preview/take/resume через serve.

Пробелы:

- Все изменения перехода начинаются в момент команды; порядок и смещения (`after`, `with`, `offset`, `overlap`) — M5c.
- Разворот таймлайна идёт с начала таймлайна (каналы — с текущих значений), а не обратным ходом `out`.
- `invoke` на слое состояния меняет пропсы экземпляра локально (`ctx.set`): следующее изменение тех же данных канала перепишет их. Гол как изменение данных — таблица реакций, M5e.
- Состояния в `keyfill schema` идут по алфавиту, а не в порядке объявления.

### Статус M5a (2026-10-16): готово — анимация геометрии

Решения пользователя: включается явно (`transition.layout`, `all` её не включает — старые сцены и снапшоты не меняются); `Box` анимирует место и размер, `Text` — только место.

- **Устройство.** `FrameNode` хранит два прямоугольника: `rect` — место в раскладке (по нему `must`, якоря, контентный блок текста) и `shown` — где узел виден (рисование, рамки просмотрщика, дамп). `shown` = видимое место родителя + место относительно родителя + своё смещение. Смещение — четыре дорожки (x, y, w, h) в `MotionState` от «было видно» к нулю; новая перестройка посреди переезда начинает дорожку с текущего смещения, пружина сохраняет скорость.
- **Моменты сверки.** `Session::relayout` снимает геометрию (`layout::geometry`: место относительно родителя и размер, без анимации геометрии) до и после пачки команд; `Session::layout_event` — до и после ухода узла из раскладки: конец `out` и новое событие `Hide` снятия экземпляра (раньше снятие сравнивалось с часами, теперь это событие, и состояние «перед ним» можно снять). Моменты известны аналитически, поэтому кадр не зависит от отрисованных кадров (тест: кадры подряд = сразу нужный момент).
- `sweep` в `advance` работает до ближайшей команды или ухода, а не до конца запрошенного интервала: иначе при прыжке вперёд узел удалялся бы из дерева раньше, чем снята раскладка в момент его ухода. Тест `journal_jump_keeps_leaving_items_until_their_out_ends`: прыжок по журналу далеко вперёд даёт тот же кадр, что живая сессия.
- Preview (`quiet_time`) ждёт и конца переездов после уходов.
- Дамп: `(видно → место)  [layout 22%]` у узла, который сам едет; `inspect` — строка `layout` и канал `layout` со смещением.
- Примеры: строки `examples/standings` и подложка табло едут (`spring.snappy`/`gentle`); подложка `examples/lower-third` плавно сужается после ухода точки и растёт под длинное имя, `clip: true` открывает текст по мере роста. Снапшоты обновлены.
- Тесты (`crates/keyfill-cli/tests/layout.rs`): перестановка, уход соседа, высота контейнера, `must` во время роста, прерывание, независимость от пути к кадру, живой канал = журнал (пружины, прерывание, две пачки на кадре).

Пробелы:

- Переезд между родителями (элемент перешёл в другой контейнер) и между экземплярами — морфинг, M5d.
- Часть с якорем к части другого экземпляра едет за видимой частью, но собственный `layout` у такого узла не учитывается.
- Размер текста не анимируется: при смене кегля (`fit`) текст встаёт в новый размер сразу.

## 14. Открытые вопросы

- Нужна ли компиляция JSX в стиле Solid (меньше аксессоров в коде) или явные аксессоры лучше для агента? После M1: с проверкой `signal.untracked` явные аксессоры выглядят достаточными; вернуться, если агенты будут часто на неё натыкаться.
- `contrast` по реальным пикселям (через рендер) вместо подложек предков: нужен для текста поверх картинок и градиентов.
- Видео как источник внутри сцены (декодирование, синхронизация с часами) — в каком виде и когда.
- Шейдерные эффекты (blur фона, glow, свои фильтры): Vello ограничен, нужны свои проходы на wgpu (см. M8 и раздел о display list). Открыто: какие эффекты получают и CPU-реализацию, а какие живут только на GPU с запасным видом.
- Формат записи внешних данных (`data track`) для детерминированного рендера.
- Как агент получает картинку через MCP: PNG целиком, уменьшенная копия или только по запросу.
